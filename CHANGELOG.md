# Изменения

## v1.2.0 — 29.10.2026

Дублирование постов в мессенджер MAX и более частое расписание.

### MAX (max.ru)
- `scraper/app/max_client.py` — клиент Bot API: `send_text`, `send_photo`,
  `send_post`, `me`, `chats`. База `https://platform-api2.max.ru`,
  `Authorization: <raw token>` без `Bearer`.
- Фото: `POST /uploads?type=image` → загрузка → `attachments[].payload.token`;
  при `attachment.not.ready` до 4 повторов с растущей паузой.
- Длинный текст не влезает в подпись к фото — остаток досылается отдельным
  сообщением (лимит 4000 символов).
- `POST /publish/max?post_id=N` — дублирование поста; ошибка MAX не роняет
  публикацию в Telegram (`success=false` в ответе).
- `GET /max/me`, `GET /max/chats` — проверка токена и поиск `chat_id` канала.
- Новые настройки: `MAX_BOT_TOKEN`, `MAX_CHAT_ID`, `MAX_API_BASE`, `MAX_PUBLISH`.
  Пустой токен или `chat_id` — дублирование тихо пропускается.
- n8n `publisher.json`: узел `Publish to MAX` после `Confirm Publication`.

### Расписание
- Публикация: `0 9-21/2 * * *` (7 слотов: 09, 11, 13, 15, 17, 19, 21 по
  Новосибирску) вместо 2 слотов 11:00 / 19:00.
- `MAX_PUBLICATIONS_PER_DAY=10` — дневной предохранитель, учитывает и ручные
  одобрения.

## v1.1.0 — 29.10.2026

Скрапер и канал приведены к рабочему состоянию на реальных товарах WB.

### Сбор данных
- **Фото товара**: добавляли `image_url` / `image_urls` в `ProductData`, берём из
  `og:image` карточки. Раньше фото не собирались вообще.
- **Хосты basket-XX**: картинки лежат на произвольном хосте (`basket-44` для
  артикула `1195565901`), поэтому URL читаем из мета-тега, а не перебором 1–30.
- **Цена**: селектор `.price-block__final-price` устарел — финальная цена в
  единственном `<ins>`.
- **Характеристики**: вместо `.product-params__row` — обычная таблица `table tr`.
- **Отзывы**: публичный API `feedbacks1/2.wb.ru/feedbacks/v2/{imtId}` вместо
  DOM-парсинга, который перестал работать после перехода WB на SPA.
- **imtId**: поиск первого числа после подстроки `imtId` — шаблон с кавычками
  срабатывал через раз.
- **Антибот**: ожидание title «купить за» (до 3 перезагрузок), полный UA Chrome,
  `--disable-blink-features=AutomationControlled`, viewport 1366×900.
  Проверять «imtId в HTML» нельзя: главная страница тоже его содержит, из-за
  этого в карточку попадал заголовок главной.
- **Очередь**: добавлен фоновый `queue_worker` — без него товары в статусе
  `queued` висели навсегда.

### Автоподбор товаров
- `scraper/app/niches.py` — сезонные категории по месяцам (Новый год и подарки,
  зима, уборка/рассада, дача, школа/спорт, осень) + круглогодичный пул.
- `scraper/app/discovery.py` — поиск WB через Playwright (API `search.wb.ru`
  отдаёт 403), фильтр по рейтингу ≥ 4.5, отзывам ≥ 50, цене 200–8000 ₽,
  не более 2 товаров с одного запроса.
- `POST /discovery/run?count=N` — разовый подбор.
- Ежедневный воркер в 08:00 по Новосибирску, `DISCOVERY_PER_DAY` (по умолчанию 8).
- `MAX_PUBLICATIONS_PER_DAY` поднят до 10.

### Публикация
- Пост уходит **в канал с фото**: JPEG-эндпоинт `/products/{id}/image.jpg`
  (WB отдаёт только webp, Telegram его не принимает — перекодируем через Pillow).
- n8n скачивает картинку сам (`Get Image`, response format = file), потому что
  Telegram не может ходить по внутреннему адресу `scraper:8000`.
- Если пост короче 950 символов — он целиком идёт подписью к фото (одно
  сообщение). Длиннее — фото с шапкой плюс отдельное сообщение с текстом.
- Кнопка «Одобрить» публикует сразу, не дожидаясь слотов 11:00/19:00.
- Пост ограничен 600–900 символами, чтобы помещаться в подпись (лимит 1024).

### Форматирование
- LLM отдаёт markdown, конвертируем в Telegram-HTML (`**жирный**` → `<b>`,
  дефисы в списках → `•`, разделители → `━`). Legacy Markdown не понимает
  `**жирный**` и печатал звёздочки как есть.
- Новый промпт: заголовок, цена 💰, рейтинг ⭐, плюсы 👍, минусы 👎,
  нюансы ❓, кому подойдёт 🎯, артикул 📦.

### Исправленные ошибки n8n
- `callback_data` и `text` были без префикса `=` — в сообщение подставлялись
  литеральные `{{ $json.article }}`, а кнопки несли `approve_{{ ... }}`,
  из-за чего `product_id` приходил `null`.
- После узла с фото `$json` — это ответ Telegram, поэтому все поля надо брать
  через `$('Split Posts').item.json.*`; иначе второе сообщение приходило пустым.
- Webhook не регистрировался: пробел в имени ноды (`Telegram Update`) давал путь
  `telegram%20update`, который не совпадал с декодированным входящим запросом.
  Нода переименована в `TelegramUpdate`.
- Подтверждение публикации падало: `message_id` лежит в `$json.result.message_id`.

### Запуск
- `ЗАПУСТИТЬ.bat` — поднимает Docker, scraper, n8n, туннель, обновляет
  `N8N_PUBLIC_URL`, проверяет сервисы и открывает панель. Ярлык на рабочем столе
  создаётся отдельно (`WB Reviews.lnk`).

### Известные ограничения
- Туннель `trycloudflare` меняет адрес при каждом перезапуске контейнера —
  после рестарта нужно снова обновить `N8N_PUBLIC_URL` и переактивировать
  workflow «WB Reviews - Bot». Для постоянной работы нужен именованный
  Cloudflare Tunnel или сервер с доменом.
- Дневной лимит публикаций считается по `published_at`; при ручном
  подтверждении публикации лимит не проверяется.
